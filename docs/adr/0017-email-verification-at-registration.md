# ADR 0017: ยืนยันอีเมลตอนสมัครด้วยบริการส่งอีเมลภายนอก (ต่อยอด ADR-0011)

## สถานะ
ยอมรับแล้ว (ตัดสินใจใน wayfinder map-v2, ticket 058/061 — ยังไม่ได้ implement) ต่อยอด ADR-0011 ไม่ได้แทนที่

## บริบท
ปัจจุบันการสมัครไม่ยืนยันอีเมลและล็อกอินให้ทันที ใครสมัครด้วยอีเมลของใครก็ได้ การแชร์แบบจำกัดอีเมล (ADR-0018) ให้สิทธิ์ตามอีเมลของบัญชีที่ล็อกอิน การจำกัดจึงไม่มีความหมายถ้าไม่พิสูจน์ว่าเจ้าของอีเมลคือผู้ล็อกอิน ADR-0011 กำหนดให้ Identity เขียนเอง ไม่ใช้ `UserManager` ซึ่งเป็นที่มาของโค้ดสร้างลิงก์ยืนยันตามเอกสาร ASP.NET Core ที่ใช้ตรงๆ ไม่ได้ และระบบยังไม่มีการส่งอีเมลเลย

## การตัดสินใจ
- **สมัครเสร็จยังไม่ล็อกอิน** ต้องกดลิงก์ยืนยันในอีเมลก่อนถึงล็อกอินและใช้แอปได้ (บัญชีที่ล็อกอินได้ทุกบัญชีจึงยืนยันแล้ว)
- ลิงก์ยืนยันหมดอายุ **24 ชั่วโมง** ส่งซ้ำได้ พักระหว่างครั้ง 60 วินาที ไม่เกิน 5 ครั้งต่อชั่วโมงต่อบัญชี และจำกัดการสมัคร/ขอส่งซ้ำต่อ IP ต่อชั่วโมง (ตัวเลขตั้งต้น ปรับได้)
- ส่งอีเมลผ่าน **บริการส่งอีเมลภายนอก** (API หรือ SMTP ของบริการ; ยังไม่เลือกเจ้า); ส่งไม่สำเร็จ → การสมัครยังสำเร็จ (บัญชียังไม่ยืนยัน) มีปุ่มส่งซ้ำ และบันทึกลง Error Log (ADR-0016)
- ปุ่มส่งซ้ำต้องทำงานตอนยังไม่ล็อกอิน (ส่งโดยระบุอีเมล) และตอบข้อความเดียวกันเสมอไม่ว่าอีเมลนั้นมีในระบบหรือไม่
- ไม่เพิ่มการเปลี่ยนอีเมลใน v2; บัญชีเดิมลบพร้อมข้อมูลเดิม
- dev ในเครื่องใช้ตัวรับอีเมลจำลอง (Mailpit/smtp4dev) ใน docker-compose

## ผลที่ตามมา
- `User` มีสถานะยืนยันอีเมล และต้องสร้าง/ตรวจ token ยืนยันเอง (ไม่ใช้ `UserManager`); ADR-0011 ยังใช้ได้ในส่วนที่เหลือ
- ถ้าอีเมลตกสแปมหรือส่งไม่สำเร็จ ผู้ใช้ใช้แอปไม่ได้จนกว่าจะส่งซ้ำสำเร็จ (ผลที่รับทราบแล้ว)
- ต้องมีโดเมนที่แก้ DNS ได้เพื่อตั้งที่อยู่ผู้ส่ง/SPF/DKIM **ยังไม่มี** — ต้องจัดหาก่อนส่งอีเมลจริง
- ARCHITECTURE.md หัวข้อ Auth และ Local development ต้องแก้ตาม (docker-compose ไม่ได้รันแค่ PostgreSQL อีกต่อไป)
