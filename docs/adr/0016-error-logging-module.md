# ADR 0016: Error Log ใน Module ใหม่ Logging (schema `logging`) ที่ Module อื่นเขียนเข้าได้

## สถานะ
ยอมรับแล้ว (ตัดสินใจใน wayfinder map-v2, ticket 055 — ยังไม่ได้ implement)

## บริบท
ตอนนี้เมื่อโค้ดล้ม ASP.NET ตอบ 500 และพิมพ์ลง console เท่านั้น (ไม่มีตัวดักข้อผิดพลาดกลางใน `Web.Jotwai` แม้เอกสารเดิมจะอ้างถึง `ExceptionHandler.cs`) งานเบื้องหลังดัก Error เองแล้วลง `ILogger` จึงตรวจย้อนหลังไม่ได้เมื่อ process ปิด Error Log เป็นของที่ทุก Module (API, งานเบื้องหลัง) ต้องเขียนลงไป ไม่ผูกกับเรื่องใดเรื่องหนึ่ง

## การตัดสินใจ
- สร้าง **Module ใหม่ Logging** มี schema `logging` และ DbContext ของตัวเอง เป็นข้อยกเว้นที่ Module อื่นเขียนลง Logging ได้ในฐานะ cross-cutting (ไม่ผ่าน Domain Event ที่ต้องรอ consume เพราะ Error Log ต้องเขียนได้แม้ระบบกำลังมีปัญหา)
- **เก็บ**: Exception ของคำขอ API ที่ตอบ 500, งานเบื้องหลังที่ล้ม, การเรียกบริการภายนอกที่ล้ม (AI/Gemini, การส่งอีเมล ฯลฯ); **ไม่เก็บ** 400/401/404/409 และ Error ฝั่งหน้าเว็บ
- **ข้อมูลต่อรายการ**: เวลา, ที่มา (คำขอ API หรืองานเบื้องหลัง+ชื่องาน), วิธี+path+รหัสสถานะ, ชนิด+ข้อความ+stack trace ของ Exception, Id ผู้ใช้ (ไม่ใช่อีเมล), request id (ส่งกลับให้หน้าเว็บเพื่อค้นหา)
- **ห้ามเก็บ**: เนื้อหา/ชื่อ Note, body ของคำขอ, อีเมล, query string, header Authorization และข้อมูลอ่อนไหวตามกฎ Security ของ repo (ต้องตรวจว่าข้อความ Exception ของ EF/Gemini ไม่พาค่าข้อมูลติดมา)
- เก็บ Error ซ้ำทุกครั้งเป็นแถวแยก; ลบแถวที่เก่ากว่า 6 เดือนโดยงานลบรันเดือนละครั้ง (แถวอยู่ได้นานสุดราว 7 เดือน); ดูผ่านฐานข้อมูลโดยตรงเท่านั้น ไม่มีหน้าจอและไม่มีสิทธิ์ผู้ดูแลระบบ
- ถ้าเขียนลงฐานข้อมูลไม่ได้ ให้เขียนลง console และห้ามให้การบันทึก log ทำให้คำขอของผู้ใช้ล้มเพิ่ม

## ผลที่ตามมา
- ตาราง Module ใน ARCHITECTURE.md เพิ่ม Logging และเป็น Module แรกที่ยอมให้ Module อื่นเขียนเข้าได้ตรง (ข้อยกเว้นจาก ADR-0002 ที่ตั้งใจ)
- ต้องเพิ่มตัวดักข้อผิดพลาดกลางใน `Web.Jotwai` (และแก้ ARCHITECTURE.md/ADR-0010 ที่อ้าง `ExceptionHandler.cs` ซึ่งยังไม่มีในโค้ด)
