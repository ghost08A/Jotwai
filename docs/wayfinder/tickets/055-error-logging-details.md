## Question

(`requirements-v2.md` §2.1) เป้าหมายสรุปแล้ว แต่ต้องตัดสิน: ข้อมูลที่จะเก็บในแต่ละ Error Log (เวลา, request, exception, อื่นๆ), ข้อมูลอ่อนไหวที่ห้ามเก็บ (ตามกฎ Security ของ repo), อายุการเก็บ/การลบ, ใครเข้าดู Log ได้และดูอย่างไร, และ Exception ชนิดใดนับ/ไม่นับ

## Progress (ตอบแล้วบางส่วน — ticket ยังเปิดอยู่)

เจ้าของโปรเจกต์ตอบ (2026-10-06):

- **เก็บ Error ชนิดไหน**: (1) คำขอ API ที่ล้มจริง (500) (2) งานเบื้องหลังที่ล้ม (3) เรียก AI (Gemini) ไม่สำเร็จ — **ไม่เก็บ** ความผิดที่คาดไว้ (400/401/404/409) และ Error ฝั่งหน้าเว็บ
- **เก็บอะไรในแต่ละรายการ**: เวลา, ที่มา (คำขอ API หรืองานเบื้องหลัง+ชื่องาน), วิธี+path และรหัสสถานะ, ชนิด+ข้อความ+stack trace ของ Exception, Id ผู้ใช้ (ไม่ใช่อีเมล), request id ที่ส่งกลับให้หน้าเว็บด้วย
- **ห้ามเก็บเด็ดขาด**: เนื้อหา/ชื่อ Note, body ของคำขอ, อีเมล, query string, header Authorization (รวมกฎ Security เดิม: password/token/secret/connection string) — ตอนออกแบบต้องตรวจว่าข้อความ Exception ของ EF/Gemini ไม่พาค่าข้อมูลติดมา
- **อายุการเก็บ**: ลบเมื่อเก่ากว่า **6 เดือน** โดยงานลบรัน **เดือนละครั้ง** (ผลคือแถวหนึ่งอยู่ได้นานสุดราว 7 เดือนก่อนถูกลบ)
- **ใครเข้าดู**: เจ้าของโปรเจกต์/นักพัฒนาเปิดฐานข้อมูลตรงๆ ไม่มีหน้าจอ ไม่มีสิทธิ์ผู้ดูแลระบบใหม่
- **Module เจ้าของ**: Module ใหม่ **Logging** มี schema ของตัวเอง

ยังไม่ได้คำตอบ: Error ซ้ำเก็บอย่างไร / ถ้าเขียนลงฐานข้อมูลไม่ได้ทำอย่างไร (Q6)

## Resolution

เจ้าของโปรเจกต์ตัดสินครบ (2026-10-06) Error Logging:

- **เก็บ Error ชนิดไหน**: (1) คำขอ API ที่ล้มจริง (500) (2) งานเบื้องหลังที่ล้ม (3) เรียก AI (Gemini) ไม่สำเร็จ — ไม่เก็บความผิดที่คาดไว้ (400/401/404/409) และ Error ฝั่งหน้าเว็บ
- **เก็บอะไรในแต่ละรายการ**: เวลา, ที่มา (คำขอ API หรืองานเบื้องหลัง+ชื่องาน), วิธี+path และรหัสสถานะ, ชนิด+ข้อความ+stack trace ของ Exception, Id ผู้ใช้ (ไม่ใช่อีเมล), request id ที่ส่งกลับให้หน้าเว็บด้วย
- **ห้ามเก็บเด็ดขาด**: เนื้อหา/ชื่อ Note, body ของคำขอ, อีเมล, query string, header Authorization (รวมกฎ Security เดิม: password/token/secret/connection string) — ตอนออกแบบต้องตรวจว่าข้อความ Exception ของ EF/Gemini ไม่พาค่าข้อมูลติดมา
- **อายุการเก็บ**: ลบเมื่อเก่ากว่า 6 เดือน โดยงานลบรันเดือนละครั้ง (แถวหนึ่งอยู่ได้นานสุดราว 7 เดือน)
- **ใครเข้าดู**: เจ้าของโปรเจกต์/นักพัฒนาเปิดฐานข้อมูลตรงๆ ไม่มีหน้าจอ ไม่มีสิทธิ์ผู้ดูแลระบบใหม่
- **Module เจ้าของ**: Module ใหม่ **Logging** มี schema ของตัวเอง
- **Error ซ้ำ**: เก็บทุกครั้งเป็นแถวแยก (ไม่รวมนับ) — ถ้าท่วมจริงค่อยตัดสินใหม่
- **ถ้าเขียนลงฐานข้อมูลไม่ได้**: เขียนลง console แทน และห้ามให้การบันทึก log ทำให้คำขอของผู้ใช้ล้มเพิ่ม
