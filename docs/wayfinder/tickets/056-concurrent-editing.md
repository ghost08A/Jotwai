## Question

(`requirements-v2.md` §2.3) ยังไม่ตัดสินวิธี: เมื่อ Client บันทึกข้อมูลที่ไม่ใช่ล่าสุด ระบบทำอะไร (แจ้งเตือน, reload, ถาม, merge, อื่นๆ) ครอบคลุมการแก้ส่วนไหนบ้างของ Entity ที่รวมแล้ว และสัมพันธ์กับ autosave อย่างไร (ต้องไม่กลายเป็น version history ซึ่งยังเป็น non-goal)

## Resolution

เจ้าของโปรเจกต์ตัดสินครบ (2026-10-06) Concurrent Editing / Stale Data:

- **เมื่อแท็บที่ข้อมูลเก่ากดบันทึก (ชน)**: **ไม่เขียนทับ** หยุด autosave ของแท็บนั้นและแสดงแถบเตือนให้ผู้ใช้เลือก 3 อย่าง: (1) โหลดเวอร์ชันล่าสุดมาแทน (ข้อความที่พิมพ์ค้างในแท็บนั้นหาย) (2) ใช้ของแท็บนี้เขียนทับ (ของเวอร์ชันล่าสุดหาย) (3) คัดลอกข้อความของแท็บนี้เก็บก่อน แล้วโหลดเวอร์ชันล่าสุด — **ไม่มีการรวมข้อความอัตโนมัติ และไม่ใช้ CRDT/Yjs/ระบบเขียนร่วมกันสด** (ไม่ขัดกับ Markdown เป็นต้นฉบับและข้อห้าม real-time)
- **ขอบเขตการป้องกัน**: เฉพาะ **เนื้อหา** — การเปลี่ยนชื่อ/ย้าย Note แม่/Category/ลบ ที่อีกแท็บทำไป ไม่นับเป็นการชนของการบันทึกเนื้อหา (เป็นการกดทำเฉพาะครั้ง)
- **Note ถูกลบ (เข้าถังขยะ) จากแท็บอื่น**: ใช้ขั้นตอนเดียวกัน แต่ข้อความเตือนเป็น "Note นี้ถูกลบแล้ว" ให้เลือก: คัดลอกข้อความเก็บ / กู้ Note คืนแล้วบันทึกของแท็บนี้ / ทิ้ง
- **แท็บเก่ารู้ตัวก่อนพิมพ์**: ตอนผู้ใช้กลับมาที่แท็บ หน้าเว็บ**ถามเซิร์ฟเวอร์เองว่ามีเวอร์ชันใหม่ไหม** ถ้าแท็บไม่มีข้อความที่ยังไม่บันทึก โหลดเวอร์ชันใหม่ให้อัตโนมัติ ถ้ามีข้อความค้างใช้ขั้นตอนชนข้างบน (ไม่ใช่ระบบอัปเดตสด — ไม่มีเซิร์ฟเวอร์ส่งข่าวมาหาหน้าเว็บ)
- **เวอร์ชันของแท็บที่ถูกชน**: อยู่แค่ในหน้าเว็บของแท็บนั้นจนกว่าผู้ใช้เลือก ไม่เก็บสำเนาสองเวอร์ชันฝั่งเซิร์ฟเวอร์ (ไม่ใช่ประวัติเวอร์ชัน — ยังเป็น non-goal) และให้เบราว์เซอร์ขึ้นเตือน "ยังมีข้อความที่ไม่ได้บันทึก" ตอนปิดแท็บ **เฉพาะช่วงที่ค้างสถานะชนอยู่**
- **การเขียนทับโดย AI**: ใช้การป้องกันเดียวกัน — ถ้าเนื้อหาของ Note ที่จะถูกเขียนทับเปลี่ยนไปหลังที่ AI คำนวณ (**Content Polish ยืนยัน** และ **ยืนยัน Merge**) ต้องบอกผู้ใช้และไม่ยืนยันให้เอง

**ไม่ได้ตัดสิน (ขั้นออกแบบ)**: วิธีเก็บเลขเวอร์ชัน/รูปแบบ API, การตั้งค่า CORS ถ้าใช้ header เช่น If-Match, การบันทึกตอนปิดแท็บ (ข้อจำกัดของ `sendBeacon` ตั้ง header ไม่ได้และจำกัด 64 KiB ตาม research 050) — **หมายเหตุ**: ข้อกำหนดการเตือนตอนปิดแท็บข้างบนใช้ได้เฉพาะช่วงสถานะชน ไม่ได้ตัดสินว่าจะบันทึกอัตโนมัติตอนปิดแท็บปกติหรือไม่

**ผลต่อเอกสาร (ขั้นเอกสารปิดท้าย ยังไม่แก้ไฟล์)**: GLOSSARY หัวข้อ Note ("แก้ไขจะ overwrite ทับของเดิม ไม่มี version history" ต้องเพิ่มว่ามีการตรวจการชนตอนบันทึกเนื้อหา แต่ยังไม่มีประวัติเวอร์ชัน); ARCHITECTURE.md/Content Polish flow และ Topic Suggestion Merge flow เพิ่มขั้นตรวจเนื้อหาไม่เปลี่ยนก่อนยืนยัน
