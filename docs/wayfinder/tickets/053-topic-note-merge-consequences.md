## Question

เมื่อ Topic และ Note เป็น Entity เดียวกัน ([ticket 049](049-topic-note-merge.md)) สิ่งเดิมต่อไปนี้ต้องเป็นอย่างไร — ห้าม assume ถามเจ้าของโปรเจกต์ทีละข้อ: (1) Category ผูกกับอะไร (2) Note ที่ปัจจุบันอยู่ได้โดยไม่มี Topic (3) ชื่อ/Title และกฎชื่อซ้ำของพี่น้อง (4) soft delete/Trash และกฎลบ Topic ที่มีลูก (5) Search read model (6) AI Categorization / Topic Suggestion (Merge, Placement) / Content Polish (7) Module ไหนเป็นเจ้าของ Entity ที่รวมแล้ว (8) ข้อมูลที่มีอยู่แล้ว (migration — ระดับ "จะรักษาไหม" ไม่ใช่ขั้นตอน) (9) ศัพท์ใน CONTEXT.md ที่จะเปลี่ยน

### รอบ 3 (2026-10-06)

- **Category**: ยังมีอยู่เหมือนเดิม ไม่เปลี่ยน (ติดที่ Note)
- **ชื่อชนตอนกู้คืนจากถังขยะ**: ปฏิเสธการกู้และให้เปลี่ยนชื่อก่อน ไม่เปลี่ยนชื่อให้เงียบๆ

- **คำว่า "Topic"**: เลิกใช้ทุกที่ (UI/โค้ด/เอกสาร) เปลี่ยนเป็น Note — ชื่อฟีเจอร์ที่ได้รับผลกระทบ (Topic Suggestion, Topic Reference, Topic Browser/Detail, Topic Sharing/Description) ยังไม่ได้ตั้งชื่อใหม่
- **ชื่อของ Note (ถ้อยแถลงของเจ้าของโปรเจกต์ ข้อ Search)**: "มีแค่ Note ที่บรรทัดแรกคือชื่อของ Note และเก็บชื่อไว้ค้นได้คล้าย Topic" — **อาจแทนที่คำตอบรอบ 2 ว่า "ชื่อ 1 ช่องแยกจากเนื้อหา"** กำลังถามยืนยันและรายละเอียด (บรรทัดแรกว่าง, กฎชื่อพี่น้องซ้ำ, ต้องเป็น heading ไหม)

## Resolution

เจ้าของโปรเจกต์ตัดสินครบ (2026-10-06) ผลกระทบของการรวม Topic+Note ([ticket 049](049-topic-note-merge.md)):

1. **ชื่อ Entity**: **Note** — คำว่า "Topic" เลิกใช้ทุกที่ (UI/โค้ด/เอกสาร) ชื่อฟีเจอร์ที่เคยมีคำว่า Topic (Topic Suggestion, Topic Reference, Topic Browser/Detail, Topic Sharing, Topic Description) ต้องตั้งชื่อใหม่ — ยังไม่ได้ตั้ง
2. **รูปร่างของ Note**: เก็บชื่อของตัวเอง เนื้อหา Markdown และรู้ว่าเป็นลูกของใคร (ไม่มีแม่ = Note ระดับบนสุด) ไม่มีแนวคิด "Note ที่ยังไม่ได้จัดเข้า Topic" แยกอีก
3. **ชื่อ**: เก็บเป็น**ช่องแยกจากเนื้อหา** หน้าตาในแอปเหมือนปัจจุบัน (ชื่ออยู่บนสุด เนื้อหาข้างล่าง ไม่บังคับ H1 ใน Markdown) **ชื่อพี่น้องใต้แม่เดียวกันซ้ำได้ แต่แสดงคำเตือน** (แทนที่กฎ "ห้ามซ้ำ" เดิม — ต้องยกเลิก unique index เดิมของชื่อ Topic)
4. **การลบ/ถังขยะ**: ลบ Note ที่มีลูก → ลูกทุกระดับเข้าถังขยะทั้งต้น; กู้แม่ = ลูกกลับครบทั้งต้น; กู้ลูกตัวเดียวขณะแม่ยังอยู่ในถังขยะไม่ได้ หมายเหตุ: คำตอบ "ชื่อชนตอนกู้ → ปฏิเสธ" (รอบ 3) ตอบก่อนที่จะอนุญาตชื่อซ้ำ จึง**ไม่มีผลแล้ว** (ชื่อซ้ำไม่ใช่ error อีกต่อไป กู้ได้ตามปกติและแสดงคำเตือนชื่อซ้ำเหมือนปกติ) — บันทึกตามเหตุผล ไม่ได้ถามยืนยันซ้ำ
5. **Category**: ยังมีอยู่เหมือนเดิม ติดที่ Note
6. **Search**: เหมือนเดิม — substring จาก ชื่อ + เนื้อหา (รวม code block) + ภาษา code block + ชื่อ Category; กรองตามแม่นับลูกทุกระดับ; ไม่นับถังขยะ
7. **AI 3 ตัว** (Categorization / Topic Suggestion / Content Polish): เงื่อนไข trigger เหมือนเดิม ทำงานกับ Note ที่รวมแล้ว **Merge**: ไม่ปฏิเสธเมื่อทั้งสอง Note มีเนื้อหา; ผู้รอดเป็น Note เดิมเสมอ (ชื่อ/ตำแหน่ง/ลูกของ Note ใหม่ย้ายมาอยู่ใต้ Note เดิม) ผู้ใช้เลือกเรื่องเนื้อหาตอนยืนยัน: เก็บของเดิมอย่างเดียว / ของใหม่อย่างเดียว / ต่อใหม่ท้ายเดิม / ต่อเดิมท้ายใหม่ — รายละเอียดที่เหลือแยกเป็น [ticket 060](060-merge-details-after-note-merge.md)
8. **Module เจ้าของ**: Module **Notes** เป็นเจ้าของ Note ทั้งก้อน (ชื่อ เนื้อหา ลำดับชั้น ถังขยะ) Module Organization เหลือ **Category อย่างเดียว** — ต้องบันทึกเป็น ADR (กระทบ ADR-0001 ถึง 0003 และตาราง Module ใน ARCHITECTURE.md)
9. **ข้อมูลเดิม**: ลบทิ้งได้ ไม่ต้อง migrate ฝาก: หลัง build เสร็จให้เพิ่มข้อมูลตัวอย่างให้เจ้าของโปรเจกต์เห็นภาพ (เป็นงาน implementation เปิด ticket ตอน build ไม่ใช่ที่นี่)

### รายการศัพท์ CONTEXT.md ที่ต้องเปลี่ยน (ยังไม่แก้ไฟล์ — ทำในขั้นเอกสารปิดท้าย)

- **Note**: เขียนใหม่ — มีชื่อ, เนื้อหา, แม่/ลูก (ลึกไม่จำกัด), Category; ตัดข้อความเรื่อง "ไม่มี Title แยก", "Note อยู่ได้โดยไม่มี Topic", unique 1 Note ต่อ Topic, ถังขยะของ Note ตัวเดียว
- **Topic**: ลบ entry (รวมกฎชื่อพี่น้อง unique และกฎลบ Topic ที่มีลูก ซึ่งถูกแทนที่ด้วยข้อ 3–4)
- **Topic Reference**, **Topic Suggestion**: เปลี่ยนชื่อ (ยังไม่ตั้ง) และปรับกฎ Merge (ข้อ 7)
- **Content Polish**: ตัดการอ้างถึง "heading แรกสุดที่ทำหน้าที่ Title" (ปัจจุบันชื่ออยู่ช่องแยก)

- **ARCHITECTURE.md**: ตาราง Module (Notes/Organization), flow ของ Topic Suggestion, non-goals (แชร์/ไฟล์แนบ ตามที่ตัดสินแล้วใน map)
