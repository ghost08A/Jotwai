## Question

(`requirements-v2.md` §2.4) ต้องตัดสิน: ความยาวสูงสุดของ Description, ระบบสร้าง/อัปเดตอัตโนมัติเมื่อใด, ถ้าผู้ใช้เขียนเองแล้วระบบหยุดสร้างทับหรือไม่, Description ถูกใช้กับ AI flow ใดบ้าง (Categorization / Topic Suggestion / Content Polish) และข้อมูลใดบ้างที่ส่งให้ AI เป็น Context

## Resolution

เจ้าของโปรเจกต์ตัดสินครบ (2026-10-06) Description ของ Note (เดิมเรียก Topic Description):

- **รูปแบบ**: ข้อความธรรมดาสั้นๆ **ช่องเดียว แยกจากเนื้อหา** ไม่มีการจัดรูปแบบ ไม่ปนในไฟล์ Markdown ของเนื้อหา
- **ความยาวสูงสุด**: **200 ตัวอักษร** (นับเป็นตัวอักษร เพราะภาษาไทยไม่มีช่องว่างคั่นคำ) ใช้ขีดจำกัดเดียวกันทั้งข้อความที่ AI สร้างและที่ผู้ใช้เขียน
- **สร้างเมื่อไร**: AI สร้าง **ครั้งเดียวอัตโนมัติ** ตอนบันทึกครั้งแรกที่มีเนื้อหาจริง (เหมือน AI Categorization) หลังจากนั้นสร้างใหม่ได้เฉพาะตอนผู้ใช้กดปุ่ม "สร้างใหม่" เอง (ข้อเสียที่รับทราบ: เนื้อหาเปลี่ยนมากแล้ว Description อาจล้าสมัยจนกว่าผู้ใช้จะกดสร้างใหม่)
- **Description ที่ผู้ใช้เขียนเอง**: ถ้าผู้ใช้เคยเขียนหรือแก้แล้ว **ระบบห้ามสร้างทับเองเด็ดขาด** AI สร้างใหม่ได้เฉพาะตอนกดปุ่ม "สร้างใหม่" และต้องมีขั้นยืนยันก่อนเขียนทับของผู้ใช้ ถ้าผู้ใช้ลบจนว่าง = **คืนสิทธิ์ให้ AI สร้างให้ใหม่ได้อีก** (ไม่ได้หมายถึง "ไม่ต้องมี Description") — หมายเหตุ: คำตอบของ Q4 พิมพ์มาเป็น "d 2" ผู้บันทึกอ่านว่าคือ "ก" (ตำแหน่งปุ่ม ก บนแป้นพิมพ์ไทยตรงกับ d) + ข้อ (2) ตามตัวเลือกที่เสนอ
- **AI ที่ใช้ Description เป็นข้อมูล**: **Topic Suggestion** (Description ของ Note ใหม่ + ของ Note เดิมทุกตัวที่ใช้เปรียบเทียบ), **AI Categorization** (Description ของ Note นั้นเอง) — **Content Polish ไม่ใช้** (กันไม่ให้ AI เติมเนื้อหานอกต้นฉบับ)
- **Topic Suggestion ส่งอะไรให้ AI ตอนเปรียบเทียบ**: **ชื่อ + Description ของ Note เดิมทุกตัว** (ไม่มีขั้นกรองก่อน — ถ้า Note เยอะมากจนช้าหรือแพง ค่อยตัดสินใหม่ภายหลัง; ยังไม่ได้วัดว่า "เยอะมาก" คือกี่ตัว)
- **Search**: **ไม่ค้นจาก Description** (ค้นเฉพาะ ชื่อ + เนื้อหา + ภาษา code block + ชื่อ Category ตามที่ตัดสินใน ticket 053)

**ไม่ได้ตัดสิน**: ผู้รับลิงก์แชร์เห็น Description ไหม — ถามใน [ticket 058](058-topic-sharing-details.md); ตำแหน่ง/หน้าตาที่แสดง Description ใน UI; วิธีสร้างเบื้องหลัง (ผ่าน outbox หรือไม่) เป็นขั้นออกแบบ; การลบ Description ตอนที่ Note ถูกลบ/กู้คืน

**ผลต่อเอกสาร (ขั้นเอกสารปิดท้าย ยังไม่แก้ไฟล์)**: GLOSSARY เพิ่มคำ "Description" (และข้อความอธิบายกฎ User Ownership ของ Description), หัวข้อ Topic Suggestion/AI Categorization (ข้อมูลที่ส่งให้ AI เพิ่ม Description), ARCHITECTURE.md flow ของ AI ทั้งสอง
