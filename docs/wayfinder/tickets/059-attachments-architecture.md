## Question

(`requirements-v2.md` §2.6) ต้องตัดสินทุกข้อที่เอกสารระบุว่ายังไม่ตัดสิน: Module เจ้าของ Attachment, ที่เก็บไฟล์จริง, รูปแบบ Key, ชนิดไฟล์ที่รองรับ, ขนาด/จำนวนสูงสุด, การแสดงรูป inline, การ download, การจัดการไฟล์เมื่อลบ Topic/Note, และ Attachment ถูกแชร์ไปกับ Topic Share หรือไม่

## Progress (ตอบแล้วบางส่วน — ticket ยังเปิดอยู่)

เจ้าของโปรเจกต์ตอบรอบ 1 (2026-10-06):

- **ชนิดไฟล์**: รับเฉพาะรายการที่กำหนดไว้ (allowlist) — รูป (png, jpg, gif, webp) แสดงในเนื้อหา, ไฟล์ทั่วไป (pdf, txt, md, csv, docx/xlsx/pptx) เป็นแถวดาวน์โหลด (ไม่รวม svg/html/exe/สคริปต์) — เรื่อง "ไม่สแกนไวรัส + ไฟล์ที่ไม่ใช่รูปเป็นดาวน์โหลดเท่านั้น" ผู้ตอบไม่ได้ตอบแยก ถามยืนยันต่อ
- **เพดาน**: 10 MB ต่อไฟล์, ไม่จำกัดจำนวนต่อ Note, พื้นที่รวม 500 MB ต่อผู้ใช้
- **ที่เก็บไฟล์จริง**: บริการเก็บไฟล์แบบ **S3-compatible** (ตัวเลือก ค) — ยังไม่เลือกผู้ให้บริการ (นอก scope ของ map นี้)
- **การลบ**: ผู้ใช้ลบรูป/ไฟล์ออกจากเนื้อหา → ไฟล์ถูกเก็บกวาดเมื่อไม่มีใครอ้างถึงเกิน 7 วัน (เผื่อ undo/กู้); Note เข้าถังขยะ → ไฟล์คงไว้; ไม่เพิ่มฟีเจอร์ลบ Note ถาวรใน v2 (ไฟล์ของ Note ที่ลบแล้วจึงกินพื้นที่ต่อไป)
- **วิธีเพิ่มไฟล์**: วางรูปจากคลิปบอร์ด, ลากไฟล์มาวาง, พิมพ์ `/` เลือก "รูปภาพ/ไฟล์"; รูปคลิกเพื่อดูภาพขยาย; ไฟล์ที่ไม่ใช่รูปเป็นแถว (ชื่อ ขนาด ปุ่มดาวน์โหลด)
- **ผู้รับลิงก์แชร์**: เห็นรูปในเนื้อหาและดาวน์โหลดไฟล์ได้เฉพาะของ Note ใต้ Note แม่ที่แชร์; ลิงก์ปิด/หมดอายุแล้วไฟล์ต้องเปิดไม่ได้ทันที; ไฟล์ของ Note นอกขอบเขตเปิดไม่ได้เด็ดขาดแม้เดา key ได้
- **คัดลอกบล็อกรูปไปวางใน Note อื่น**: คำตอบ "ก็อปไปวางได้เลย ใส่ key ไปตรงจุดนั้นของ Note" — กำกวมระหว่าง "อ้าง key เดียวกันข้าม Note" กับ "ระบบคัดลอกไฟล์ให้" (ถามต่อ)

ข้อขัดกันที่ต้องแก้: ที่เก็บแบบ S3-compatible + ลิงก์ชั่วคราว (presigned URL) ที่ออกไปแล้วใช้ได้จนหมดอายุ ขัดกับ "ปิดแล้วเปิดไม่ได้ทันที" (ถามต่อ)

## Resolution

เจ้าของโปรเจกต์ตัดสินครบ (2026-10-06) Image/File Attachments:

- **ชนิดไฟล์**: รับเฉพาะรายการที่กำหนด (allowlist) — รูป (png, jpg, gif, webp) แสดงในเนื้อหา; ไฟล์ทั่วไป (pdf, txt, md, csv, docx/xlsx/pptx) แสดงเป็นแถวให้ดาวน์โหลด; ไม่รับ svg/html/exe/สคริปต์ **ไม่สแกนไวรัสใน v2** และไฟล์ที่ไม่ใช่รูปเป็น "ดาวน์โหลดเท่านั้น" ไม่เปิดในเบราว์เซอร์ (ถ้าต้องการสแกนจริง เป็นเรื่องใหม่ที่ยังไม่ได้ศึกษา)
- **เพดาน**: 10 MB ต่อไฟล์, ไม่จำกัดจำนวนต่อ Note, พื้นที่รวม 500 MB ต่อผู้ใช้ (สำเนาที่ระบบคัดลอกให้ตามข้อ "คัดลอกข้ามหน้า" นับรวมด้วย)
- **ที่เก็บไฟล์จริง**: บริการเก็บไฟล์แบบ **S3-compatible** — ยังไม่เลือกผู้ให้บริการ (นอก scope ของ map นี้; การทำให้ dev ในเครื่องใช้ได้ เช่น ตัวจำลอง S3 ใน docker-compose เป็นขั้นออกแบบ)
- **การส่งไฟล์ให้ผู้ใช้/ผู้รับลิงก์แชร์**: **API ดึงไฟล์จาก S3 แล้วส่งต่อให้ทุกครั้ง** ตรวจสิทธิ์ทุกครั้ง (ไม่แจกลิงก์ชั่วคราว presigned URL ให้เบราว์เซอร์) เพื่อให้ปิด/หมดอายุลิงก์แล้วเปิดไฟล์ไม่ได้ทันที ตามกฎของ ticket 058; ถ้าภายหลังภาระของ API หนักเกินไป ย้ายไปใช้ลิงก์ชั่วคราวอายุสั้นเป็นการตัดสินใจใหม่
- **ผู้รับลิงก์แชร์**: เห็นรูปในเนื้อหาและดาวน์โหลดไฟล์ได้ เฉพาะไฟล์ของ Note ที่อยู่ใต้ Note แม่ที่แชร์; ลิงก์ปิดหรือหมดอายุแล้วไฟล์เปิดไม่ได้ทันที; ไฟล์ของ Note นอกขอบเขตเปิดไม่ได้เด็ดขาดแม้เดา key ได้
- **ไฟล์เป็นของ Note ใด Note หนึ่ง**: คัดลอกบล็อกรูป/ไฟล์ไปวางใน Note อื่น → **ระบบคัดลอกไฟล์ให้ Note ปลายทางอัตโนมัติ** ได้ key ใหม่ตรงจุดที่วาง ผู้ใช้เห็นรูปขึ้นตามปกติ ไม่ต้องนับการอ้างข้าม Note
- **การลบ**: ผู้ใช้ลบรูป/ไฟล์ออกจากเนื้อหา → ไฟล์ถูกเก็บกวาดเมื่อไม่มีใครอ้างถึงเกิน **7 วัน** (เผื่อ undo/กู้); Note เข้าถังขยะ → ไฟล์คงไว้; **ไม่เพิ่มฟีเจอร์ลบ Note ถาวรใน v2** จึงรับทราบว่าไฟล์ของ Note ที่ลบแล้วกินพื้นที่ต่อไป (ยังนับในเพดาน 500 MB ของผู้ใช้)
- **วิธีเพิ่มไฟล์**: วางรูปจากคลิปบอร์ด, ลากไฟล์มาวางในหน้า Note, พิมพ์ `/` แล้วเลือก "รูปภาพ" หรือ "ไฟล์"; รูปคลิกเพื่อดูภาพขยาย; ไฟล์ที่ไม่ใช่รูปเป็นแถว (ชื่อ ขนาด ปุ่มดาวน์โหลด)
- **Module เจ้าของ "ข้อมูลของไฟล์"** (ชื่อไฟล์ ขนาด ชนิด Note ที่สังกัด key): Module **Notes** (ตัวไบต์อยู่ใน S3) — Module เจ้าของ Share ยังไม่ตัดสิน (ดู map ส่วน Not yet specified)
- **รูปแบบใน Markdown**: รูป `![ชื่อรูป](attachment:KEY)` และไฟล์ `[ชื่อไฟล์](attachment:KEY)` โดย `KEY` เป็นรหัสสุ่มยาวที่เดาไม่ได้; `attachment:` เป็นที่อยู่ภายในของ Jotwai ที่ editor แปลงเป็นรูปจริง (ในโปรแกรม Markdown อื่นจะเป็นลิงก์ที่ใช้ไม่ได้)

**ไม่ได้ตัดสิน (ขั้นออกแบบ)**: ผู้ให้บริการ S3 จริง, รูปแบบ key ที่แน่นอน, การจัดการ CORS/credentials, ตารางข้อมูลของไฟล์, ลำดับเก็บกวาดและงานเบื้องหลัง, การตรวจชนิดไฟล์จริง (ไม่เชื่อแค่นามสกุล), ขั้นตอนเมื่ออัปโหลดแล้วแต่ Note ไม่ถูกบันทึก (ไฟล์กำพร้า), การทดสอบเครื่องมือ dev

**ผลต่อเอกสาร (ขั้นเอกสารปิดท้าย ยังไม่แก้ไฟล์)**: ARCHITECTURE.md ยกเลิก non-goal "ไม่มีการแนบไฟล์/รูปภาพ", เพิ่มหัวข้อ Attachment (S3, API เป็นคนส่งไฟล์), และ ADR ใหม่; CONTEXT.md เพิ่มคำ **Attachment**; **Content Polish (ticket 054)**: เพิ่ม "อ้างอิงไฟล์แนบ `attachment:KEY` ทั้งรูปและลิงก์ไฟล์" ในรายการห้ามแตะ และเพิ่มในรายการที่คำเตือนใน preview ต้องเทียบ; **Search**: ไม่ค้นจากเนื้อหาในไฟล์แนบ (ไม่ได้ขอ), อาจค้นชื่อไฟล์ได้หรือไม่ ยังไม่ได้ตัดสิน
