## Question

ผู้ใช้ขอปุ่มให้ Nerd Assistant (เดิมชื่อ AI Categorization — ดู GLOSSARY.md/ARCHITECTURE.md ที่อัปเดตไปแล้ว) ช่วยแต่งเนื้อหา Note ให้อ่านง่ายขึ้น — grill กันจนได้ scope ที่ยืนยันแล้วดังนี้ (2026-09-27):

### ตำแหน่งปุ่มและ trigger

- Floating button มุมขวาล่างของ editor เสมอ (ไม่ผูกกับการเลือกข้อความ — ต่างจาก `NoteEditorBubbleMenu` ที่โผล่เฉพาะตอน select text)
- On-demand เท่านั้น ผู้ใช้กดเอง ไม่มี auto-trigger
- เรียก AI แบบ **sync ตรงๆ** ตอนกดปุ่ม (ไม่ผ่าน outbox/background) ผู้ใช้รอผลสดๆ หน้าจอ
- **ไม่มี state ค้างในระบบเลย** — ไม่ต้องมี entity/table เก็บผลลัพธ์ (ต่างจาก Suggestion ที่ต้องรอ resolve) ถ้าผู้ใช้ปิดหน้าไปโดยไม่กดยืนยัน ผลลัพธ์หายไปเฉยๆ

### ขอบเขตของเนื้อหาที่แตะได้

- ทำงานกับเนื้อหาทั้ง Note รวม heading แรกสุดที่ทำหน้าที่ Title ด้วย (ตั๋ว 037)
- **ห้ามแตะเนื้อหาใน code block เด็ดขาด** — เสี่ยงเกินไปที่จะให้ AI แก้โค้ดแบบไม่มี preview เชิงเทคนิคจริงจัง

### กฎการแก้ไข (สำคัญ — ต้องเขียนเป็น prompt/logic ที่ AI ทำตามได้จริง)

แก้ได้ตรงๆ โดยไม่ต้องเก็บของเดิม (ไม่เปลี่ยนความหมายที่ผู้ใช้ตั้งใจสื่อ แค่เปลี่ยนรูปแบบการเขียน):
- ตัวสะกดผิด (typo)
- ไวยากรณ์/เว้นวรรคแปลกๆ
- จัดย่อหน้ายาวๆ ให้เป็นข้อย่อย (bullet list) เพื่อให้อ่านง่ายขึ้น

ต้องเก็บของเดิมกำกับไว้ในวงเล็บเสมอ (ห้ามเปลี่ยนความหมายแบบเงียบๆ เด็ดขาด):
- ตัวเลข/ข้อมูล/ข้อเท็จจริงที่ AI ไม่มั่นใจว่าผู้ใช้ตั้งใจเขียนแบบนั้นจริงๆ หรือพิมพ์ผิด (ตัวอย่างที่ผู้ใช้ยกมา: "1+1=3" ห้ามแก้เป็น "1+1=2" เงียบๆ)
- ประโยคใหม่ที่ AI เดาเติมเข้ามาเอง ("ขยายคำอธิบาย") ที่ไม่มีในต้นฉบับเลย — ต้องทำเครื่องหมายกำกับด้วยว่าเป็นส่วนที่ AI เติมให้ ไม่ใช่คำพูดของผู้ใช้เอง

รูปแบบวงเล็บกำกับ: แทรกของใหม่ที่ AI คิดว่าน่าจะถูก/น่าจะดีกว่า พร้อมวงเล็บ "(เดิม: ...)" ต่อท้ายในเนื้อหาจริง — ผู้ใช้เห็นทั้งคู่แล้วตัดสินใจเอง ลบวงเล็บทิ้งเองทีหลังผ่านการแก้ไข Note ตามปกติถ้าไม่ต้องการ (ไม่ใช่ accept/reject รายจุดใน popup)

### Preview & ยืนยัน

- ผลลัพธ์ที่ AI แก้เสร็จ (รวมวงเล็บกำกับ) โชว์เป็น popup preview เนื้อหาทั้งฉบับ
- มีแค่ 2 ปุ่ม: **"ยืนยัน"** (overwrite เนื้อหาจริงทั้ง Note ทีเดียว รวมวงเล็บกำกับที่ยังติดอยู่) กับ **"ยกเลิก"** (ไม่มีอะไรเปลี่ยนเลย เนื้อหาเดิมยังอยู่) — ไม่มีการเลือก accept/reject เป็นจุดๆ ในนี้
- จำเป็นต้อง preview ก่อนเสมอ เพราะ Note ไม่มี version history (ตาม CLAUDE.md ground rules) — แก้แล้ว overwrite ทับของเดิมทันที กู้คืนไม่ได้ถ้า apply ไปแล้วโดยไม่ได้ตรวจก่อน

### AI provider

- เริ่มต้นใช้ Gemini tier เดิม (2.5 Flash-Lite) เหมือน AI Categorization flow — ถ้าคุณภาพการแต่งคำภาษาไทยไม่พอค่อยขยับ tier ทีหลังผ่าน config โดยไม่ต้องแก้โค้ด (provider อยู่หลัง interface อยู่แล้วตาม ADR-0004)

### Naming (ดู GLOSSARY.md ที่อัปเดตแล้ว)

- Module เปลี่ยนชื่อในเอกสารจาก "AI Categorization" เป็น **"Nerd Assistant"** — ของจริงในโค้ด (schema `ai_categorization`, class เช่น `AiCategorizationDbContext`) **ยังไม่เปลี่ยน** จะทำเป็น ticket แยกทีหลัง ticket นี้เขียนโค้ดใหม่ในโครงเดิม (schema/namespace เดิม) ไปก่อน
