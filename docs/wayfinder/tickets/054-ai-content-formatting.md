## Question

(`requirements-v2.md` §2.5) AI จัด Format แล้วเปลี่ยนโครงสร้างผิดเจตนา (เช่น ordered list → bullet ที่มีเลขข้างใน) ต้องตัดสิน: ถือการเปลี่ยนแบบไหนเป็น "เปลี่ยนโครงสร้างที่ต้องหลีกเลี่ยง" AI แก้ได้มากน้อยแค่ไหน ครอบคลุมโครงสร้างใดบ้าง (ordered/unordered/nested list, heading, code block, checkbox, blockquote) และสัมพันธ์กับกฎเดิมของ Content Polish อย่างไร

## Progress (ตอบแล้วบางส่วน — ticket ยังเปิดอยู่)

เจ้าของโปรเจกต์ตอบรอบ 1 (2026-10-06):

- **หลักการ**: AI **ห้ามเปลี่ยนชนิดของโครงสร้างที่ผู้ใช้เขียนไว้** (รายการเลข/รายการจุด/checkbox/ระดับหัวข้อ/quote)
- **ย่อหน้ายาว → รายการ**: เก็บไว้ แต่เฉพาะย่อหน้าธรรมดาที่ไม่ได้อยู่ในโครงสร้างอยู่แล้ว และสร้างได้แค่รายการจุด
- **ภายในรายการ**: ทำได้ทุกอย่าง (แก้คำผิด, ปรับถ้อยคำ, รวม/แยก/สลับลำดับข้อ, เพิ่มข้อ, ลบข้อซ้ำ, เปลี่ยนความลึกการซ้อน) **และเพิ่มเส้นคั่น กับเน้นคำสำคัญเพื่อให้อ่านง่าย** (รายละเอียด "เน้นคำ" ยังต้องถามต่อ)
- **สิ่งที่ห้ามแตะ**: ถูกทั้ง 7 (สถานะ checkbox, เลขในรายการเลข, ลิงก์ภายนอก, ตัวหนา/เอียง/ขีดทับ/inline code ที่มีอยู่, เส้นคั่นที่มีอยู่, การ์ดลิงก์ไปหน้าลูก, code block)
- **Safety net**: (ข) ดักด้วยโปรแกรมเทียบโครงสร้างก่อน-หลัง แสดงคำเตือนใน preview ผู้ใช้ยังกดยืนยันได้

## Resolution

เจ้าของโปรเจกต์ตัดสินครบ (2026-10-06) กติกา AI Content Formatting (Content Polish) ใหม่ — เปลี่ยนเฉพาะกฎเรื่องโครงสร้าง กฎอื่นของ Polish คงเดิมทั้งหมด:

**หลักการ**
- AI **ห้ามเปลี่ยนชนิดของโครงสร้างที่ผู้ใช้เขียนไว้**: รายการเลข / รายการจุด / checkbox / ระดับหัวข้อ / quote (เช่น `1. 2. 3.` ต้องยังเป็นรายการเลข ไม่กลายเป็น `- 1.`)
- ย่อหน้ายาว → รายการ: เก็บไว้ แต่ใช้เฉพาะ **ย่อหน้าธรรมดาที่ไม่ได้อยู่ในโครงสร้างอยู่แล้ว** และสร้างได้แค่ **รายการจุด** (ไม่สร้างรายการเลข/checkbox ให้เอง)

**ภายในรายการ (ไม่ใช่ checkbox)** AI ทำได้: แก้คำผิด, ปรับถ้อยคำให้อ่านลื่น, รวมข้อ, แยกข้อ, สลับลำดับข้อ, เพิ่มข้อใหม่, ลบข้อที่ **ซ้ำกันเป๊ะๆ** เท่านั้น, เปลี่ยนความลึกของรายการซ้อน — ข้อที่ AI เพิ่มต้องมีป้าย "(เพิ่มโดย AI)" เหมือนประโยคที่เติม
**รายการ checkbox (to-do)**: แก้ได้เฉพาะคำผิดและถ้อยคำ **ห้ามรวม/แยก/สลับ/เพิ่ม/ลบข้อ** (สถานะติ๊กเดิมต้องอยู่ครบ)

**เพิ่มเพื่อให้อ่านง่าย (ใหม่)**: AI เพิ่ม **เส้นคั่น** (horizontal rule) และ **ตัวหนา** เน้นคำสำคัญได้ (ใช้ mark ที่ editor มีอยู่แล้ว ไม่สร้างฟีเจอร์ "ไฮไลท์สี" ใหม่)

**ห้ามแตะ (ถูกทั้ง 7)**: สถานะ checkbox แต่ละข้อ; เลขในรายการเลขตามที่ผู้ใช้เขียน (ไม่แก้เลขให้เรียงใหม่); ลิงก์ภายนอก; ตัวหนา/เอียง/ขีดทับ/inline code ที่มีอยู่ (เปลี่ยนตัวอักษรข้างในได้ แต่ห้ามเอา mark ออก); เส้นคั่นที่มีอยู่; การ์ดลิงก์ไปหน้าลูก (Note Reference — ชื่อเดิม Topic Reference); code block ทั้งก้อน

**Safety net**: หลัง AI ตอบ ระบบเทียบโครงสร้างก่อน-หลังด้วยโปรแกรมธรรมดา (ไม่ใช้ AI) แสดง **คำเตือนใน preview** ผู้ใช้ยังกดยืนยันได้ คำเตือนเทียบเฉพาะ: (1) ชนิดรายการเปลี่ยน (เลข/จุด/checkbox) (2) ระดับหัวข้อเปลี่ยนหรือหัวข้อหาย/เพิ่ม (3) สถานะ checkbox เปลี่ยน (4) quote หาย/ถูกสร้าง (5) code block เปลี่ยน (6) การ์ดลิงก์ไปหน้าลูก หาย/ชี้เปลี่ยน (7) ลิงก์ภายนอกหาย/ที่อยู่เปลี่ยน — **ไม่เตือน** เรื่องจำนวน/ลำดับข้อ เส้นคั่นหรือตัวหนาที่เพิ่ม และย่อหน้าที่ถูกจัดเป็นรายการจุด (ข้อสังเกตจาก research 052: ยังไม่ได้พิสูจน์ว่าการเทียบนี้จับ `- 1.` ได้จริง ต้องทดสอบตอนทำ)

**กฎ Polish เดิมที่คงไว้ทั้งหมด**: แก้คำผิด/ไวยากรณ์ตรงๆ ไม่ทำเครื่องหมาย; ตัวเลข/วันที่/ชื่อ/ข้อเท็จจริงที่น่าจะผิดให้เสนอคำแก้พร้อมเก็บของเดิมใน "(เดิม: ...)"; ประโยคที่ AI เติมเองมีป้าย "(เพิ่มโดย AI)"; ผลเป็น preview กด "ยืนยัน" (overwrite ทั้งฉบับ) หรือ "ยกเลิก"; ไม่แตะเนื้อหาใน code block

**ผลต่อเอกสาร (ทำในขั้นเอกสารปิดท้าย ยังไม่แก้ไฟล์)**: CONTEXT.md หัวข้อ **Content Polish** — แก้กฎโครงสร้างตามข้างบน และตัดการอ้างถึง "heading แรกสุดที่ทำหน้าที่ Title" (ชื่อ Note เป็นช่องแยกแล้วตาม ticket 053); ARCHITECTURE.md หัวข้อ Content Polish flow เพิ่มขั้นเทียบโครงสร้างและคำเตือนใน preview
